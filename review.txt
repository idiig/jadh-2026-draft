Review 1
========

Contribution of the Submission
------------------------------
The contribution demonstrates how phrase breaks (kugire) in waka poems can be added as an interpretative annotation layer in TEI encoding. This layer is created using rule-based and translation-based methods, with the latter supported by an LLM.

Comments for the Authors
------------------------
This is a relevant contribution that addresses an actual gap: there is no reusable kugire layer for TEI-encoded waka. The authors propose an annotation scheme and a semi-automatic pipeline for adding kugire candidates. The combination of a rule-based method and an LLM-assisted, translation-based method is convincing, and the use of a local LLM is particularly welcome. Treating kugire as an interpretative layer preserving multiple candidates is conceptually strong and promising. The work builds on existing resources and shows awareness of the existing ecosystem.

Some aspects could be improved:
 
- My main concern is the TEI encoding that does not fully convince me. The custom <k> element with an @n attribute is not very explicit. It remains implicit that @n refers to the position after a specific segment. It would be helpful to discuss more explicit ways to anchor breaks. Instead of introducing a new element (which is also not described in detail in the contribution), I wonder whether existing TEI mechanisms would do the trick, e.g. <anchor> to mark positions in the text, and <interpGrp><interp> (possibly in standOff>.


<seg .... >
<anchor xml:id="n1_break_after_2"/>
<seg ....>


<interpGrp type="kugire">
 <interp target="#n1_break_after_2" source="#morph" cert="high>

- The status of the pipeline as a tool or system is not fully clear. The paper mentions the annotation pipeline in a good overview, but details remain unclear, e.g. if this exists as a reusable script-based pipeline or as a tool/interface. Are there plans to make this publicly available?

- I appreciate the detailed description of the LLM integration. In addition, it would be interesting to know how the results are evaluated. How often are suggestions accepted or corrected by the annotators? Some insight would give a good impression of the reliability of the approach.

Overall, a very interesting paper.
